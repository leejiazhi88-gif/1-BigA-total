# 持仓比例核查

核验日期：2026-10-27。适用图表：[国家队与社保已披露持仓](https://leejiazhi88-gif.github.io/1-BigA-total/#national-team-direct)。

## 计算范围

根据用户最新要求，**两条A股曲线共用同期全A股总市值**作为分母。ETF继续采用当期已识别持有基金的净资产合计作为分母。

| 曲线 | 分子 | 分母 |
| --- | --- | --- |
| 汇金／证金A股 | 当期具名账户持有A股股数 × 同期参考价，逐条加总 | 同期沪深北全部上市A股总市值 |
| 汇金／证金ETF | 当期具名账户持有基金份额 × 同期单位净值，逐基金加总 | 当期识别到持仓的基金总份额 × 同一净值，按基金去重加总 |
| 社保投资组合A股 | 当期社保具名投资组合A股股数 × 同期参考价，逐条加总 | 与汇金／证金A股相同的全A股总市值 |

比例 = 分子合计 ÷ 分母合计 × 100%。金额单位均为亿元。汇金投资、其他已识别账户两条构成线共用全A股分母，两项比例可以相加；股票与ETF分母不同，不生成两者合计比例。明细的“占该标的比例”仍为单只股票或基金的持有比例，与曲线的全市场占比区分。

A股总股本含流通与限售A股，不含H股、B股、非上市外资股、优先股。股价沿用金额模式的同一未复权期末参考价，缺少交易价格时沿用已审计的期末参考市值折算价。

全A股分母取报告期末最后交易日。沪市采用Tushare `daily_info` 的 `SH_A` 加2019年7月开市后的 `SH_STAR`，金额单位亿元；深市采用 `sz_daily_info` 的主板A股、创业板及2021年4月并板前中小板，金额单位元除以1亿。使用市场合计减B股市值交叉检查，避免板块重复计入；不使用深证成指等样本指数市值代替全市场。

北交所自2021年11月15日开市后加入，使用[官方市场统计日报](https://www.bse.cn/static/statisticdata.html)的总市值与公司家数，19个季度末原始查询值在 `work/bse_market_cap_history.json`。开市前不含新三板精选层。未使用直接逐股加总：Tushare历史逐股接口存在缺项，例如2021年末仅返回77只，而官方为82家，市值分别为2,593.94和2,722.75亿元。分母采用官方全市场值。

ETF按基金净值口径，不按二级市场成交价。总份额包括上市与未上市/场外份额；少数原始持有人表的占比仅以上市份额为分母，因此页面计算值可能略低于报告表内占比。脚本先用报告明确列出的场外份额还原上市份额，核对报告占比，再以全部基金份额计算页面比例。

## 核查结果

- 股票：3,166家公司，2015-06-30至2026-06-30的45个季度，共44,147条去重公司/季度股本。
- 全A股总市值：45个季度完整覆盖，沪深板块和B股排除交叉核对通过，北交所19期采用官方总量；保存于 `work/a_share_market_cap.json`。2015年6月分母582,086.75亿元；2025年末1,087,535.06亿元；2026年6月1,189,603.41亿元。
- ETF：从167份已识别具名持仓的原始报告取得总份额及净资产，覆盖22个中报/年报时点。
- 股本采用东方财富 `RPT_F10_EH_EQUITY` 历史结构，分页完整获取，取报告期末当日或之前最后生效且截至核验日已公告的记录，不将当前股本倒填历史。
- 单股明细继续核对A股流通与限售分项、全类别总股本、持有股数不超过A股股本、同一公司多账户价格一致；这些公司股本不再决定A股曲线的分母。
- ETF总份额与报告净资产/净值互相核对，保留单位净值披露精度造成的舍入容差；核对具名持有份额及报告列明的占比。页面分母使用总份额乘与分子完全一致的净值，以免两边舍入规则不同。
- 所有分母均有有效值，未解决核查差异为0；缺失分母、价格冲突或超额持仓会阻止构建。

## 解释限制

单只股票/基金的股数比例不受其价格影响。全市场与持仓价格同幅变化时，A股汇总比例保持不变；但持仓相对市场的表现、IPO、增发、退市和分子披露覆盖变化仍会改变结果。因此它是“可识别直接A股持仓占全市场市值”，不是净买卖指标，也不是相关机构全部资产占比。

持股公司数量不再影响分母，但仍影响可识别的分子：汇金／证金在2025年末识别220家公司，2026年中报识别35家，对应全市场占比为3.823%与2.769%。前十大股东榜外持仓无法识别，进入/退出榜单或披露缺口仍会造成变化，不能把比例变化全部解释为买卖。社保范围及其他限制沿用[社保历史核查](social-security-history-audit.md)和[直接A股历史核查](national-team-stock-history-audit.md)。

ETF季度报告及2026年中报的未披露状态原样保留，缺失比例不补零、不沿用旧份额。此功能不刷新全站行情、不变更既有持仓金额。

## 换机与重跑

换机拉取仓库后直接复用已提交的JSON，无需重新下载全部原始数据：

```bash
node work/build_market_dashboard.js --skip-refresh
```

重新核查当前历史范围时，先按README中的股票、社保、ETF流程恢复持仓和原始报告缓存，再执行：

```bash
python3 work/fetch_holding_denominators.py --stage collect
python3 work/fetch_holding_denominators.py --stage stocks
python3 work/fetch_holding_denominators.py --stage export
python3 work/fetch_a_share_market_cap.py
python3 -m unittest discover -s work -p 'test_*.py'
node --test work/test_holding_ratios.cjs work/test_national_team_direct_holdings.cjs work/test_national_team_etf_history.cjs
node work/build_market_dashboard.js --skip-refresh
```

`collect`支持断点重跑，股本原始缓存位于 `.tools/national-team-stock-history/ratio-capital-*`；ETF原文复用 `.tools/national-team-history/` 的报告JSON。`stocks`单独生成诊断，`export`重新核对股票并合并ETF，全部校验通过后才替换正式分母JSON。原始缓存不上传仓库。

全A股脚本按股本数据中的报告期自动取最后交易日，原始沪深市场统计缓存位于 `.tools/a-share-market-cap/`；北交所补期需先从官方日报核对并更新 `work/bse_market_cap_history.json`。任何市场分项缺失、日期错配或市场合计不一致都会阻止生成，未核实值不填零。缓存需要重拉时仅移走对应请求的缓存文件。换机无需这些缓存，已提交的最终JSON足以构建页面。

当前脚本的股本查询上限为2026-06-30、核验截止日为2026-10-27。以后新增报告期时，应同步调整查询上限及核验日期，更新所需原始缓存和持仓文件，再重新导出分母；不能直接套用旧日期或当前股本。若核查数据源历史修订，需要移走相应的 `ratio-capital-{code}.json` 和该代码分页缓存后重新拉取。
